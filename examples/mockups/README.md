# RAPP Work Default UI Concepts

These are deliberately lightweight reaction surfaces, not application
implementations. All three represent the same Autonomous Agent First workflow:

1. the user expresses a thought;
2. the bot reconstructs verified context;
3. it explains tradeoffs and recommends a shape;
4. the user confirms or redirects;
5. the bot applies bounded canonical work and maintains continuity.

Open `rapp-work-concept-lab.html` and switch between:

- **A · Conversation** — familiar one-bot chat with the smallest transition
  from current AI tools.
- **B · Thought Canvas** — the strongest thought-to-outcome expression; context
  surrounds the conversation without becoming controls.
- **C · Living Transcript** — distinct evidence-backed bot perspectives in one
  reconstructible conversation.

The UI is intentionally deferred. These frames exist only so the user can
react to possible passive projections after the headless collaboration is
proven.

All names, counts and dialogue are synthetic. The buttons are local UI
demonstrations, not provider APIs or evidence that any live mutation happened.
The headless manager now implements exact-root selection and native metadata
catalogs; these mockups do not connect to those APIs or expose a real roster.
